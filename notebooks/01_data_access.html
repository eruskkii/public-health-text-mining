Purpose

This notebook evaluates candidate public data sources for the Group 4 term paper on mining public health discourse.

The assignment requires a corpus of at least 50,000 documents.

We evaluate three acquisition routes:

  1. Public archived datasets
  2. GDELT news data
  3. Social media datasets

For each source, we record:

  • accessibility
  • corpus size
  • available text
  • date coverage
  • metadata
  • reproducibility
  • limitations

Access issue

The initial GDELT API test did not successfully return data.

The first request timed out after 10 seconds. A subsequent request where we increased timeout reached the server but returned HTTP status 429 (“Too Many Requests”), indicating rate limiting at the API endpoint.

This presents a potential access constraint for large-scale collection. Since the proposed corpus requires at least 50,000 documents, repeated timeouts or rate limiting could make GDELT impractical within the project’s timeframe. The source was therefore retained as a candidate but not relied upon as the sole acquisition route.

Experiment 2: Archived COVID-19 vaccine corpus

Following the access constraints encountered with the GDELT API, we investigated publicly archived social-media corpora.

We first investigated the Large-scale COVID-19 Twitter Chatter Dataset hosted on Zenodo. Although the corpus is substantially larger than the 50,000-document requirement, the archived dataset primarily distributes tweet identifiers which would need hydrating through Twitter’s API.

The University of Maryland BSOS Social Science Data Repository hosts a public mirror of the All COVID-19 Vaccines Tweets dataset originally collected by Gabriel Preda.

The repository reports 228,207 observations and 25 variables, exceeding the assignment requirement of at least 50,000 documents.

Result The latest data is from 2021. So we’re making the decision to move to a topic with more recent public discourse across a longer time frame.

Result

A six-year aggregation request for comments returned a server-side timeout. Repeating the request for 2021 only succeeded (HTTP 200), returning monthly comment counts for the full year. This suggests that Arctic Shift is viable for historical Reddit acquisition, but requests should be divided into smaller time windows.

We’re going to write a function to test this.

get_comment_counts <- function(subreddit, year) {

  start_date <- paste0(year, "-01-01")
  end_date <- paste0(year + 1, "-01-01")

  request <- request(arctic_comments_url) |>
    req_url_query(
      subreddit = subreddit,
      after = start_date,
      before = end_date,
      aggregate = "created_utc",
      frequency = "month"
    ) |>
    req_timeout(60)

  response <- request |>
    req_error(is_error = function(resp) FALSE) |>
    req_perform()

  if (resp_status(response) != 200) {
  print(resp_status(response))
  print(resp_body_string(response))
  stop(paste("Request failed for year", year))
  }

  body <- resp_body_json(
    response,
    simplifyVector = TRUE
  )
  Sys.sleep(2)
  body$data
}

get_comment_counts_with_retry <- function(subreddit, year, max_attempts = 3) {

    for (attempt in 1:max_attempts) {

        result <- tryCatch(
            get_comment_counts(subreddit, year),
            error = function(e) NULL
        )

        # retry logic...
        result <- tryCatch(
      get_comment_counts(subreddit, year),
      error = function(e) NULL
    )

    if (!is.null(result)) {
      cat("Success:", year, "\n")
      Sys.sleep(10)
      return(result)
    }

    cat("Failed:", year, "\n")

    if (attempt < max_attempts) {
      cat("Waiting 20 seconds before retrying...\n")
      Sys.sleep(20)
    }
  }

  stop(paste("All attempts failed for year", year))
}
